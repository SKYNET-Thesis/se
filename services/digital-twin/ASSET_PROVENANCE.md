requested white reference image. Phase 2 changes that material to white only
inside its viewer; geometry, transforms and joint definitions are unchanged.
The image alone does not prove the origin of a separate white asset. LeLab's
root LICENSE is Apache-2.0; the nested `so-101-urdf/package.xml` declares
`BSD` and names LycheeAI as author, but the subtree has no separate license
text. The precise redistribution terms for these CAD-derived meshes should
be confirmed before new distribution; Phase 2 reuses existing VISTA files.

relative to `se/`. SHA-256:

I/O v5.0.21. Offline parsing found 49 nodes, 34 meshes and one scene. The

The joint nodes have local quaternions and a moving-jaw child, so all six
can be targeted by a renderer. The GLB does **not** encode a verified motor
axis, sign convention, zero calibration, jaw transfer function, or explicit
units. These must be established with model/source evidence and offline pose
fixtures before physical use. The current CHECKIK viewer targets five arm
joints, rotates each around its local Y axis, and does not animate `gripper`
(`SO101DigitalTwin.tsx:6,77-119`); that is implementation behavior, not proof
that local Y is correct for every joint.

## Provenance and rights

The asset entered VISTA in commit
`8c38892125d8fcb4371b20064005f25e23c57e9a` ("chore: add VISTA docs and
CHECKIK workspace"). That history does not identify the GLB's author,
original download URL, license, or attribution conditions. The inspected
official LeLab commit `84b6251cec3471195dfa35119827fbd1da2a801e`
contains an SO-101 URDF/STL package but no tracked `.glb` or `.gltf` file.
LeLab's Apache-2.0 source license therefore cannot establish rights for
this particular VISTA GLB. **Source and redistribution permission remain
unverified.** No GLB was copied, replaced, or redistributed in Phase 1.

## MuJoCo reference

Menagerie commit `98a70c569c4c1b6da467a20012f766ee1f8dc521` includes
`robotstudio_so101/so101.xml`, `scene.xml`, meshes and a model-local Apache-2.0
LICENSE. MuJoCo 3.3.6 loaded it headlessly: six joints, six actuators, `nq=6`.
For this exact revision, named `jnt_qposadr` results are 0–5 in the order
`shoulder_pan`, `shoulder_lift`, `elbow_flex`, `wrist_flex`, `wrist_roll`,
`gripper`. Future code must resolve addresses by joint name on the loaded
model; it must not hardcode these indices. No physical-to-MJCF gripper
calibration was established.
