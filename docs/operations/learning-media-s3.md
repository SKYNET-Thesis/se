# Learning Media: S3 layout, formats, security and deployment

Scope: D02 (Course Builder media). Student submissions are D03 and are **not** implemented here.

## One bucket, key prefixes

Learning Media uses the single existing private media bucket (Terraform `aws_s3_bucket.media`, output `media_bucket`).
It is separate from the static website bucket, the AI-models bucket, robot recordings and datasets. S3 "folders" are only
key conventions; every key is generated by the API from UUIDs and a fixed allowlist, never from client input
(`services/education-api/src/modules/learning/learning-media.keys.ts`).

```text
learning-media/
  courses/<courseId>/{documents|images|videos|audio}/<mediaId><ext>      D02, issued by LearningMediaService
  submissions/<assignmentId>/<studentId>/<submissionId>/...              RESERVED for D03; never issued, read or signed by D02 code
```

- Existing objects and database rows are unchanged: the course layout already used `documents/`, `images/` and `videos/`; D02 only adds `audio/`.
- `LearningMediaStorage` refuses any key that is not a well-formed course-media key (traversal, `submissions/`, other prefixes), so a bug elsewhere cannot sign or read outside `learning-media/courses/`.
- The IAM policy is scoped to `learning-media/courses/*`, so even a code defect cannot reach `submissions/` or other prefixes.

## Supported formats (server allowlist = Course Builder picker)

| Kind | Extension -> MIME | Prefix |
|---|---|---|
| Document | `.pdf` application/pdf, `.docx`, `.pptx` (OOXML) | `documents/` |
| Image | `.png` image/png, `.jpg`/`.jpeg` image/jpeg, `.webp` image/webp (already supported before D02; kept) | `images/` |
| Video | `.mp4` video/mp4, `.webm` video/webm, `.mov` video/quicktime | `videos/` |
| Audio | `.mp3` audio/mpeg | `audio/` |

Extension and declared MIME type must match exactly. Everything else (executables, HTML, SVG, ZIP, WAV/OGG ...) is rejected before a URL is signed.
Maximum size: 250 MiB (`MAX_LEARNING_MEDIA_BYTES`, unchanged).

Content model: MP3 is attached to a **reading** activity through the existing `mediaIds` attachments and played with an HTML `<audio>` player
(editor, preview and student view). It is never placed in the video-only `videoMediaId` field. No schema or content-version change.

## Upload / download flow and checks

1. `POST /admin/courses/:courseId/media/uploads` (system admin, global non-archived course): validates name, size, extension+MIME; creates a `pending` row; returns a presigned POST valid 5 minutes bound to the exact key, Content-Type, media id metadata and exact content length.
2. Browser POSTs the file to S3.
3. `POST /admin/media/:mediaId/complete` (only the uploader): `HeadObject` must match size, Content-Type and media id; then the first 16 bytes are read (ranged GET) and must carry the format's magic number (`learning-media.signature.ts`). Any mismatch marks the asset `failed`. A pending upload with no object after 10 minutes is marked `failed`.
4. `GET /activities/:activityId/media/:mediaId/url` (learner): presigned GET valid 15 minutes, only for published content, active enrollment/classroom/membership, correct course and activity reference. `GET /admin/media/:mediaId/url` is for authors.

Content verification limits: this proves a file *starts like* its declared format. It is not malware scanning, cannot detect polyglots or Office macros, and DOCX/PPTX share the generic ZIP header. Real antivirus scanning would need extra infrastructure and is out of D02 scope.

Known behaviour: the API role has no `s3:ListBucket`, so S3 answers 403 (not 404) for a missing object; `HeadObject` then surfaces as "could not verify the uploaded object" instead of "not present". Granting ListBucket was deliberately not done (least privilege).

## Database: MP3 needs migration H (registered in the manifest, not applied to production)

`public.learning_media_assets` has a CHECK constraint `learning_media_assets_mime_type` (created by migration E) that lists the allowed MIME types.
`audio/mpeg` was not in it, so inserting an MP3 asset fails in the database. Until migration H is applied the API answers a clear
`503 "audio/mpeg uploads are not enabled in this environment yet ..."` instead of a 500; every other format is unaffected.

Migration file: `database/migrations/20261112_h_learning_media_audio_mpeg.sql` (one atomic `ALTER TABLE`: drop and re-add the constraint with the
nine previous values unchanged plus `audio/mpeg`; no row is read, rewritten or deleted; replay-safe; requires migration E).
Verification: `tests/database/test_learning_media_audio_migration.py` (static checks always; a PostgreSQL test, run in a rolled-back transaction on the
disposable database of the bootstrap workflow, proves existing rows are byte-identical, `audio/mpeg` is accepted, other types stay rejected and a replay is harmless).

Status: **Registered in the migration manifest (order 5), not applied to production.** Registration followed the repository's two-commit convention (as for migration G), because the manifest's `sourceCommit` must be a commit that already contains the SQL bytes (done: SQL in `e8e0bb7`, registration in the next commit):

1. Commit the migration file, the test and the `REQUIRED_OBJECTS` entry in `scripts/bootstrap_dev_database.py` (the manifest validator rejects an *untracked* SQL file, so bootstrap cannot run before this commit).
2. In a second commit: add the manifest entry `{version: 20261112_h_learning_media_audio_mpeg, path, sha256 of the file, order: 5}`, set `sourceCommit` to the commit from step 1, run
   `VISTA_DEV_DATABASE_URL=<empty vista_test_* db> python scripts/bootstrap_dev_database.py --confirm-local-bootstrap`, then `--verify-only --write-expectation` to refresh `database/baselines/dev-schema-expectation.json`
   (only `ledgerVersions` and `schemaFingerprint` change), and update the "D, E, F and G" wording in `database/migrations/README.md`.
3. Production/Supabase: not applied. Apply only through `scripts/sql_migration_runner.py` after release approval.

Rehearsed on disposable PostgreSQL 17 databases: the runner applied H once on a database at D-G (ledger `executed`, a second `--apply` was a no-op), and the resulting schema fingerprint is identical to a fresh bootstrap of the registered manifest.

## Infrastructure prepared (not applied)

- `infra/terraform/compute.tf`: the Education API instance role gets `s3:PutObject` and `s3:GetObject` on `<media bucket>/learning-media/courses/*` only.
- `infra/terraform/storage.tf` + `variables.tf`: media CORS allows `POST`, `HEAD` from the CloudFront default domain plus `media_cors_allowed_origins` (default `https://skynex.best`, `https://www.skynex.best`). No wildcards, no localhost, no GET.
- Block Public Access, SSE-S3 encryption, versioning, TLS-only policy and ownership controls are unchanged.

Before applying: run `terraform plan` with the remote state and review that only the IAM policy document and the CORS rule change. This was not run here.

## Environment required on the API server

Supplied through the Secrets Manager JSON `vista/<env>/education-api/env` (names only; values are not recorded here):

| Variable | Value |
|---|---|
| `LEARNING_MEDIA_BUCKET` | the `media_bucket` Terraform output |
| `AWS_REGION` | `ap-southeast-1` |

Do not set `LEARNING_MEDIA_S3_ENDPOINT` in production (the API refuses it) and do not add static AWS keys: the instance role provides credentials.
Without the two variables the media endpoints answer 503 "Learning Media storage is not configured".

## D01 / D03 boundaries
