# AWS IoT SO-101 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a safe, testable AWS IoT command/status bridge to the existing VISTA physical execution flow.

**Architecture:** The edge owns X.509 MQTT/TLS and converts versioned cloud commands into the existing fail-closed Runtime contract.  The API uses IAM-backed IoT Data Plane publish after existing session/safety gates; Digital Twin consumes telemetry read-only.

**Tech Stack:** Python 3.12/Paho MQTT, NestJS/TypeScript/AWS SDK v3, FastAPI/Pydantic, React/Vitest.

**Spec:** `docs/superpowers/specs/2026-11-06-aws-iot-so101-design.md`

## Global Constraints

- Do not mutate `infra/terraform/` or execute AWS/Terraform operations.
- Preserve the untracked `infra/terraform/iot/` directory.
- X.509 private keys remain local and are never serialized, logged, or committed.
- All physical programs continue through `PhysicalExecutionService`, Runtime validation, and CHECKIK.
