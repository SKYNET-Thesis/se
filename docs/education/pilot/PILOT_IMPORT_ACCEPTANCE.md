# Pilot content normalization and import acceptance (local, isolated)

Date: 2026-11-26. Scope: **local isolated PostgreSQL only; nothing imported into Production.** All imported questions are DRAFT.

## What was produced

- `scripts/education/normalize_pilot.py` reads (never modifies) `VISTA_Education_Content/` and writes per-lesson import files in the importer's template layout. The source directory is **not** in this repository.
- `docs/education/pilot/en-demo-course/` — the complete English demonstration course (Beginner, 6 lessons, 60 questions). Definitions translate the source's correct options; every distractor is another definition from the same lesson (the script fails if any option cannot be mapped); the explanations are newly authored from the lesson objectives (what the term means, why it matters in the lesson, the typical mix-up). `source_reference` carries `PENDING_REVIEW (generated draft, not instructor-approved)`. **No instructor approval is claimed.**
- `normalization_report.json` — counts and open issues (0 exclusions, 0 unmapped options).
- The 180 original Vietnamese questions are regenerated by the script (explanations stay as in the source — an echo of the correct option — and are flagged as a quality limitation for later instructor review).

## Rules applied

Points are left blank in every row so the importer applies the owner rule (easy 1, medium 2, hard 3); instructors override per row (file `points`) or when adding a question to a quiz. Course/lesson columns come from the curriculum file (course title, lesson order); the source has no learning sections, so `learning_section` is empty (nothing invented). The importer's outcome codes are `LO-<ordinal>` per lesson, so rows reference `LO-1` and the source outcome (LO-01…LO-18) is kept in `source_reference`. The source Bloom level "Thông hiểu / ứng dụng" is mapped to `understand`.
